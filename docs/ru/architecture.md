## L2-транспорт и L3-маршрутизация

Зафиксированы шесть system-сетей libvirt: четыре сегмента лаборатории, default NAT network для вспомогательных ВМ и неиспользуемый сегмент с DHCP. Гостевая адресация отличается от адресации мостов хоста. Мосты обеспечивают L2-транспорт; предусмотренные шлюзы находятся в гостях. Прямой L3-маршрут хоста в гостевые подсети не настроен, поэтому проверка гостей выполнялась через отдельный канал QEMU guest agent.

Default network использует NAT хоста; NAT основной лаборатории реализован внутри edge router. Режим isolated в libvirt сам по себе не доказывает полную изоляцию всех путей через хост. К неиспользуемому сегменту ВМ не подключены.

[Схема README](../../README.ru.md#архитектура) и [исходник Mermaid](../../diagrams/network-topology.mmd) показывают основную лабораторию. Шлюз LAN — `192.168.10.1`, DMZ — `192.168.20.1`, ISP-клиента — `10.10.10.1`. Default next hop edge router представлен адресом `198.51.100.2`. Статические маршруты ISP обеспечивают обратный трафик и прямой HTTP-доступ к частному адресу DMZ.

## Firewall и трансляция адресов

| Механизм | Задокументированное поведение | Проверка |
|---|---|---|
| FORWARD | DROP; established/related разрешён | Правила и контролируемые сетевые пробы |
| LAN → WAN | Правила разрешают DNS/HTTP/HTTPS/ICMP | Проверены отдельные HTTP/ICMP-потоки; DNS/TLS отсутствуют |
| LAN/WAN → DMZ | Разрешены TCP 80/443 к DMZ-узлу | HTTP проверен; TLS listener отсутствует |
| LAN MASQUERADE | LAN source заменяется WAN-адресом маршрутизатора | Счётчики и source на HTTP-узле ISP |
| WAN DNAT | `198.51.100.10` → `192.168.20.10`, только WAN ingress | HTTP 200 из ISP; LAN hairpin недоступен |
| DMZ SNAT | `192.168.20.10` → `198.51.100.10` | Правило есть; исходящий поток NOT TESTED |

DNAT задан по адресу; разрешённые транзитные порты ограничиваются фильтрацией. ISP-клиент также открывает HTTP по частному DMZ-адресу. Доступ не ограничен исключительно адресом трансляции. Новые SSH-подключения из DMZ/ISP в LAN завершались timeout; положительные контроли подтвердили работающие listeners. См. [полную матрицу](validation.md).

## Сохранение конфигурации

Edge router восстанавливает `/etc/iptables/rules.v4` через `lab-firewall.service` с ранним systemd-порядком и ifupdown pre-up gate. Статические интерфейсы и sysctl сохраняют адреса и forwarding. Повторяемая команда `ip addr replace` не скрывает ошибки второго адреса. ISP router восстанавливает маршруты через `lab-routes.service` и sysctl. Оба HTTP-узла используют `lab-web.service`.

После поочерёдных перезагрузок гостей сохранённые и действующие правила совпали: шесть filter и три NAT. Адреса, маршруты, forwarding и необходимые units восстановились. В наблюдаемом boot firewall завершился до ifup/networking. Перезагрузка хоста, намеренный отказ загрузки firewall и непрерывный packet capture всего boot не проверялись.

WAN отображён через TEST-NET `198.51.100.0/24`: основной transit `.0/30`, второй `.8/30`. Это документальная замена, а не готовая конфигурация развёртывания. Идентификаторы ВМ, динамические tap-имена и внутренние XML исключены.
