## Исправленные проблемы

Ранее два ручных Python HTTP-сервера работали от root из привилегированного домашнего каталога и показывали directory listing с чувствительными именами файлов. Содержимое учётных данных не читалось. Первичное исправление заменило эти процессы на `lab-web.service`, пользователя `www-data` и выделенный document root `/srv/www/html`.

Итоговая проверка подтвердила только `CAP_NET_BIND_SERVICE`, `NoNewPrivileges=yes`, `ProtectHome=yes`, `ProtectSystem=strict`, `PrivateTmp` и `PrivateDevices`. Статический каталог принадлежит root с режимом 0755, файлы — root с 0644; процесс видит контент только для чтения. Проверки restart/reboot и искусственные escape-пробы прошли. Эти ограниченные пробы не доказывают защиту от всех HTTP-атак. Python `http.server` остаётся учебным узлом без TLS.

Поздний запуск firewall исправлен: загрузка до активации интерфейсов, зависимости networking и ifupdown gate. Второй WAN-адрес задаётся через `ip addr replace` без подавления ошибок. Существующие filter/NAT policy и разрешённые порты сохранены.

## Остаточные риски

| Область | Фактическая граница |
|---|---|
| Управление маршрутизатором | INPUT/OUTPUT ACCEPT; подключённые сегменты могут обращаться к SSH маршрутизатора |
| SSH | В исходных гостях для обычных пользователей остаётся password authentication; root login только по ключам; login/authentication не проверялись. [Политика только по ключам с инструментами проверки](ssh-hardening.md) теперь есть, но к ним не применялась |
| Транзитная изоляция | Проверены выбранные IPv4-пути; альтернативные пути через хост, все протоколы и IPv6 не аттестованы |
| Доступ к DMZ | ISP открывает HTTP как по адресу трансляции, так и по частному адресу |
| HTTP / DNS | В описанной лаборатории нет TLS (необязательная непроверенная роль TLS описана в разделе [инфраструктура как код](infrastructure-as-code.md)) и гостевого DNS; работа по IP |
| Восстановление | Проверены конфигурационные копии; нет независимого off-host backup всей системы и restore drill |
| Загрузка | Один guest reboot-цикл; reboot хоста и намеренный отказ загрузки firewall не проверены |
| Порядок в инвентаризации | Сохранены одинаковые гостевые hostname и неиспользуемая сеть; реальные имена исключены |

В наблюдаемой загрузке каждого гостя остаются одна ошибка AF_VSOCK CID и одна ошибка завершения необязательного SSH generator. Устройство VSOCK не настроено; TCP SSH, QGA и необходимые службы работали, failed units — ноль. Generator не отключали ради скрытия сообщений. Точная временная причина не установлена; работоспособность VSOCK SSH не заявляется. Полный CVE-аудит, проверка аутентификации и adversarial security assessment не проводились.

Репозиторий описывает учебную среду. Он не разрешает открывать работающую лабораторию в Интернет и не заявляет production readiness, коммерческих клиентов или сертификаты.

## Очистка перед публикацией

Включены только отобранные Markdown, одна Mermaid-схема, `.gitignore` и локальная проверка. Реальные имена ВМ/доменов заменены условными ролями. Исключены UUID, MAC, boot ID, личные hostname, данные домашней сети, личные пути, внутренние XML, сырая диагностика, приватные файлы привилегированного пользователя, backup, диски, учётные данные и скриншоты. Исходные рабочие скрипты аудита, изменения и перезагрузки не распространяются. Каталог `infra/` — отдельный, заново написанный эталонный код без заимствований из них; проверка публикации охватывает и его.

WAN представлен TEST-NET `198.51.100.0/24`: маршрутизатор `.1`, ISP `.2`, адрес DMZ `.10`; transit `.0/30` и `.8/30`. Частные адреса LAN/DMZ/ISP относятся к лаборатории, а не к домашней сети. Замена затрагивает только документацию.

Для рабочего дерева выполните `python3 scripts/check_public.py`, для committed blobs — `python3 scripts/check_public.py --git-ref HEAD`. Скрипт отклоняет неразрешённые файлы, symlink, нетекстовые данные, шаблоны идентификаторов/ключей/учётных данных и IPv4 вне документированных диапазонов лаборатории. Он выводит только имена файлов и категории, без найденных значений. Скрипт не обращается к сети или гостям и не требует сторонних библиотек. Поиск шаблонов не заменяет чтение каждого файла и проверку Git author metadata.

Перед публикацией проверьте всё содержимое, ссылки, Git status, staged names и автора коммита. После push повторно проверьте committed blobs и дерево/коммит на GitHub. `.gitignore` уменьшает риск случайного добавления, но не очищает уже отслеживаемые файлы и историю. Будущие изменения требуют такой же проверки. Для изменения видимости GitHub нужно отдельное согласие владельца после проверки приватной загрузки.
