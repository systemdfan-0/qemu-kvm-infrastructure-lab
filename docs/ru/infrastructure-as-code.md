# Воспроизводимая лаборатория (инфраструктура как код)

[Главная](../../README.ru.md) · [English](../en/infrastructure-as-code.md) | **Русский**

## Статус и честное предупреждение

Файлы в [`infra/`](../../infra/) воссоздают лабораторию **по опубликованной документации**. Это **не** исходные рабочие скрипты изменений (они остаются приватными, см. [безопасность](security.md)), и они **не** запускались целиком на свежих гостях. Числа в [проверках](validation.md) относятся к исходной лаборатории, а не к этому коду.

| Компонент | Что реально проверено |
|---|---|
| XML сетей libvirt | `xmllint` и `virt-xml-validate` проходят |
| `lab.sh` | `bash -n`; просмотрен полный `--dry-run` для `up`. Ни одна ВМ не создавалась |
| Ansible | `--syntax-check`, `ansible-lint` и `yamllint` проходят; шаблоны отрисованы из инвентаря |
| Firewall | Сгенерированный `rules.v4` (режимы open и strict) принят `iptables-restore --test`, пример nftables — `nft -c`; оба в непривилегированном сетевом namespace |
| Защита SSH | Drop-in принят `sshd -t`; проверки действующей конфигурации сверены с реальным выводом `sshd -T`; клиентская проба испытана на временных локальных `sshd` (см. [ssh-hardening](ssh-hardening.md)) |
| `site.yml` и `verify.yml` на настоящих гостях | **Не запускались** |

Считайте первый настоящий запуск проверкой самого кода, ожидайте небольших правок и читайте каждую задачу перед запуском.

## Что создаётся

Шесть гостей Debian 13 (по умолчанию 1 vCPU, 512 МиБ) в пяти сетях libvirt:

| Сеть | Режим | Назначение |
|---|---|---|
| `lab-lan`, `lab-dmz`, `lab-wan`, `lab-isp` | Изолированный L2-мост, без адреса на хосте и DHCP | Четыре сегмента лаборатории |
| `lab-mgmt` | NAT, `192.168.150.0/24`, статические аренды | Доступ Ansible и единовременная установка пакетов |

Объекты называются `lab-*` / `labbr-*`, а сеть управления использует отдельный диапазон, поэтому сборка может сосуществовать с уже существующей лабораторией. Скрипт пропускает всё, что уже существует, и не изменяет это.

## Быстрый старт

Нужно: libvirt (`qemu:///system`), `virt-install`, `qemu-img`, ваш пользователь в группе `libvirt`, `ansible-core` на управляющей машине и образ Debian 13 *genericcloud* (qcow2) с `cloud.debian.org` с проверенными контрольной суммой и подписью.

```bash
sudo install -d -o "$USER" -g libvirt /var/lib/libvirt/images/qemu-kvm-lab
cp debian-13-genericcloud-amd64.qcow2 /var/lib/libvirt/images/qemu-kvm-lab/base.qcow2
export LAB_BASE_IMAGE=/var/lib/libvirt/images/qemu-kvm-lab/base.qcow2
export LAB_SSH_PUBKEY=~/.ssh/id_ed25519.pub     # файл ПУБЛИЧНОГО ключа
infra/libvirt/lab.sh --dry-run up
infra/libvirt/lab.sh up
```

Дождитесь загрузки гостей, затем:

```bash
cd infra/ansible
ansible-playbook playbooks/site.yml             # пакеты, адресация, firewall, web, защита SSH
ansible-playbook playbooks/verify.yml           # матрица трафика (только чтение)
ansible-playbook playbooks/audit_ssh.yml        # аудит SSH (только чтение)
```

Чтобы удалить лабораторию, выполните `infra/libvirt/lab.sh destroy` из корня репозитория: скрипт спросит подтверждение и затрагивает только объекты `lab-*`.

## Решения и отличия от исходной лаборатории

- **Сетевой интерфейс управления.** В исходной лаборатории его не было (гостей осматривали через QEMU guest agent). Ansible нужен путь, поэтому у каждого гостя есть `enp1s0` в `lab-mgmt`. Это осознанное, документированное отличие; оно же позволяет маршрутизаторам принимать SSH только отсюда, не открывая его всем сегментам.
- **Нет Интернета внутри лаборатории.** NAT нужен только для того, чтобы `bootstrap.yml` установил пакеты. Он добавляет *временный маршрут по умолчанию только в памяти*, ставит всё нужное (включая пакеты для необязательных TLS и защиты SSH) и снова удаляет маршрут. Статическая конфигурация cloud-init не содержит default route, поэтому у маршрутизатора ISP по-прежнему нет маршрута по умолчанию.
- **Имена интерфейсов.** `enp2s0…` предполагают virtio-интерфейсы в порядке создания на гостях q35. Роль `network` завершится понятной ошибкой, если интерфейса нет; задайте `lab_interfaces` в инвентаре.
- **Маршруты.** Статические маршруты ISP-маршрутизатора записаны строками `post-up` в ifupdown вместо исходного `lab-routes.service`. Результат тот же, механизм другой.
- **Firewall.** `lab-firewall.service` загружает `/etc/iptables/rules.v4` до `network-pre.target`, а интерфейсы пограничного маршрутизатора имеют `pre-up` gate, не позволяющий им подняться раньше. Правила соответствуют [архитектуре](architecture.md): FORWARD DROP; LAN→WAN DNS/HTTP/HTTPS/ICMP; LAN и WAN→DMZ TCP 80/443 на веб-узел; WAN DNAT опубликованного адреса; LAN MASQUERADE; DMZ SNAT.
- **Политика INPUT.** `edge_input_mode: open` (по умолчанию) сохраняет описанный INPUT ACCEPT. `strict` ставит DROP по умолчанию, разрешает SSH только из сети управления и LAN (с ограничением частоты) и меняет проверку 11 матрицы с «открыто» на «закрыто». Используйте `-e edge_input_mode=strict` и повторите `site.yml` и `verify.yml`. Эквивалентный нативный набор правил: [`infra/examples/edge-router.nft`](../../infra/examples/edge-router.nft).
- **Веб-узлы.** `lab-web.service` запускает `python3 -m http.server` от `www-data` только с `CAP_NET_BIND_SERVICE`, `NoNewPrivileges`, `ProtectSystem=strict`, `ProtectHome`, `PrivateTmp` и `PrivateDevices`; отдаёт каталог root только для чтения с явным `index.html` (без листинга каталога).

## Добавление TLS (необязательно)

Описанная лаборатория отдаёт обычный HTTP. `web_tls_enabled: true` добавляет HTTPS-listener перед тем же содержимым:

```bash
ansible-playbook playbooks/site.yml -e web_tls_enabled=true
```

`stunnel4` завершает TLS 1.2+ на порту 443 и передаёт трафик на локальный HTTP-сервис; самоподписанный ECDSA-сертификат один раз создаётся на госте. Самоподписанный выбран намеренно: в лаборатории нет DNS и публичного имени, поэтому публичный УЦ не выдаст сертификат, и клиенты должны явно доверять ему. Существующие правила FORWARD и DNAT уже разрешают порт 443 на веб-узел. Чтобы оставить только HTTPS, привяжите обычный listener к loopback (`web_bind: 127.0.0.1`, `web_port: 8080`). Вне лаборатории используйте внутренний УЦ или ACME с настоящим именем, короткими сроками и контролем продления. Эта роль не запускалась на госте.

## Известные пробелы

Нет off-host backup, DNS, правил IPv6, мониторинга, политики автообновлений; `verify.yml` проверяет только TCP. Это указано намеренно; см. также [безопасность](security.md).
